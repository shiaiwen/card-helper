# 网站部署

域名 `95chong.cn` 的解析在阿里云。子域名和主域名使用同一台服务器的公网 IP，站点由服务器按主机名分开。

## 子域名 xc.95chong.cn

`xc.95chong.cn` 指向这台服务器上的另一个项目。阿里云只负责把域名解析到服务器；进哪个项目由服务器上的站点配置决定。

### 阿里云解析

登录阿里云，打开 `95chong.cn` 的云解析，添加一条记录：

| 栏           | 值                                       |
| ------------ | ---------------------------------------- |
| 记录类型     | `A`                                      |
| 主机记录     | `xc`                                     |
| 解析请求来源 | 默认                                     |
| 记录值       | 与 `95chong.cn` 已有 A 记录相同的公网 IP |
| TTL          | `10 分钟`                                |

保存后完整域名是 `xc.95chong.cn`。记录值填公网 IP，不填项目目录、端口或内网地址。

本机确认解析：

```bash
nslookup xc.95chong.cn
```

返回地址与主域名 A 记录一致即生效。

### 服务器

同一台机器上已有站点占用 80 端口时，用 Nginx 按主机名转发到另一个项目。将该项目实际监听的端口替换下面的 `端口`：

```nginx
server {
    listen 80;
    server_name xc.95chong.cn;

    location / {
        proxy_pass http://127.0.0.1:端口;
        proxy_set_header Host $host;
    }
}
```

另一个项目若是静态文件，用 `root` 指向它的目录，不要用 `proxy_pass`。

检查并重载：

```bash
nginx -t
```

通过后再重载 Nginx。之后 `http://xc.95chong.cn` 进入该项目，主域名仍走原来的站点。

该项目的监听端口尚未记入本文，配置前需在服务器上确认。

## 子域名 gx.95chong.cn

自助观星代码在本仓库同级目录 `guanxing`，不在本仓库里。用户打开页面时请求 `/api/report`，服务端当次重新下载 `Config_w.sgs`。文件内容或日期变了就重新生成报告。

### 阿里云解析

再加一条 A 记录，主机记录填 `gx`，记录值与 `95chong.cn` 的公网 IP 相同（当前是 `123.56.3.130`）。

### 构建与进程

本地开发和发布都在同级目录 `guanxing` 里执行，不要用本仓库的 `npm run dev` 或 `npm run deploy`。那个目录里 `npm run dev` 是本地页面，`npm run deploy` 会构建并上传到服务器 `/opt/guanxing`，再重启监听 `127.0.0.1:17322` 的进程。说明写在该项目的 `开发.md`。上传走 SSH，目标默认是 `admin@123.56.3.130`。

第一次先在本机把公钥装到服务器，之后这条命令不再询问密码：

```bash
ssh-keygen -t ed25519
ssh-copy-id admin@123.56.3.130
```

进程退出后由同级项目里的 `deploy/keep-alive.sh` 再拉起。这台服务器没有 `/etc/systemd/system`，不用 `guanxing.service`。

### Nginx

同级项目里的 `deploy/guanxing.nginx.conf` 按主机名把 `gx.95chong.cn` 转到 `127.0.0.1:17322`。放进站点配置后 `nginx -t`，通过再重载。

小抄里的「自助观星」按钮打开 `https://gx.95chong.cn/`。证书沿用主站的 `/etc/nginx/ssl/fullchain.cer` 和 `/etc/nginx/ssl/95chong.cn.key`。
