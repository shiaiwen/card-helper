# 自动挂机与自动任务实现分析（对照 app.bak）

本文记录 app.bak 中“自动挂机”“盖主速刷”“自动任务”的实现方式，作为后续独立迁移的依据。迁移时参考其思路自行实现，不引用 app.bak / legacy 代码。

- 分析对象：`.reference/app-bak/xiaochao.js`，反混淆后的可读版本在 `.dev-data/appbak/xiaochao-pretty.js`（由 `.dev-data/appbak/deobf.cjs` 生成，文中行号均指该文件）。
- legacy（`src/legacy/xiaochao-legacy.js`）中有同一套逻辑的旧版本（`autoBotSwitch` 引用 31 处），可交叉对照。
- 项目定位：免费、为爱发电，**不迁移 VIP 授权**。app.bak 把 `autoBotSwitch`、`autoHGSwitch` 放在 VIP 特性集合中（约 16195 行 `Ff`），新工程直接开放。

## 2. 开关与模式

### 2.1 `autoBotSwitch` 取值（`DA = new Set([1, 9, 11, 28, 29])`）

| 值 | 模式 | 局内入口 |
|---|---|---|
| `true` / 1 | 普通挂机 | `iE.loop('auto', deal, 1000)` |
| 9 | 盖主速刷（配合小号） | `OU(this)` |
| 11 | 单骑无双（肉鸽 1v1） | `OC(this)`，提示“小杀助手接管挂机” |
| 28 | 国战托管房（模式 28/22） | 循环 `stageMoveHandler()` 或 `deal()` |
| 29 | 八人身份老友 | `OC(this)` |

- `Du(value)`：把存储值规范成上述取值。
- `DT(value)`：根据当前模式名（`topMenu.areaServerLabel.text`）和 `GameContext.GetModeVO()` 校正取值，例如在“国战”下自动切到 28、在“八人身份老友”下切到 29。
- `autoHGSwitch`：盖主速刷子开关，与 9 联动；`baiShengSwitch`：百胜战功子开关（普通挂机下使用），两者共用 UI 上同一个复选框（`DS()` 按当前模式切换文字与提示）。
- `extraAssistSwitch`：进阶辅助（另见 §5.1 清单）。

### 2.2 运行 ID 与取消

- `ig.autoBotRunId`，`xI()` 读取当前值；每次启动 `+1`（约 13375 行）。
- 所有异步步骤都用 `xN(undefined, runId)` 判断“挂机仍开启且仍是同一轮”，否则立即放弃。这是防止旧轮次的延时回调在关闭或重启后继续操作的核心手段，迁移时必须保留。
- 停止（约 13507 行）：清定时任务 `qF()`（`auto`、`autoS`、`autoBotTip`、`autoBotRestore`、`autoBotRoomListWatch`、`autoBotRoomCreate`、`autoHGRestart`、`baiShengNextGame`、`autoSurrenderRogue1v1`、`autoBotTavernTarget`），复位各标志。

### 2.3 状态持久化

- `localStorage.XC_AUTO_BOT_STATE` 保存挂机状态（约 12740–12753 行），页面重载或断线重连后据此恢复。
- 清缓存白名单 `BF` 中保留该键。

## 3. 局内出牌决策（`this.deal`）

`deal` 在接管 `gamescene` 时（`seatUIs` 方法内）以闭包定义，每秒由 `iE.loop('auto')` 调用。流程：

1. `OR(...)`：百胜战功等特殊流程优先处理。
2. `LY()`：有可点的“取消/不出”类提示按钮时直接点掉（`btnCancel` 或 `sendData == 0`）。
3. `L4()`：读取当前操作请求（是否 `actionable`、需要选几张牌、目标座位等）；`Ls()` + `L6()`：有明确选项时直接执行 `Ll`。
4. `Ow()`：当前操作不被允许时点取消并 `Oi()`。
5. `ZH(request)`：命中内置特殊规则（黄盖、隐匿等）时按规则执行 `ZG`。
6. `ql()`：满足托管条件时切到游戏托管（`trustee`）。
7. `Dn()` 为假（不能用官方 AI）：直接走本地规则 `Lr(order, [0,1,2,3])`。
8. 否则进入官方 AI 流程（`ai`），带状态 `autoDecisionState`：
   - `fallbackLevel = 0`：尝试官方推荐 `L5()` / `Lh()`；返回 `acted` 视为已执行，`invalid` 计失败。
   - 超过等待阈值（常量 `Oj`、`Oo`、`Ou`）仍无结果 → `fallbackLevel = 1`，改走本地规则。
   - 本地规则持续超过 `OQ` → `fallbackLevel = 2`，调用 `LW()` 进一步兜底（托管）。

### 3.1 三种出牌来源

| 状态 | 含义 | 判定 |
|---|---|---|
| `ai` | 游戏内置小杀 AI 推荐 | `DQ()`：演武模式（74）或 `GetModeVO().TrusteeAiManual` 或 `GameContext.CanOpenAiHelp` |
| `local` | 脚本本地规则 | 官方不可用或超时 |
| `trustee` | 游戏自带托管 | `ql()`；或点击 `onTrusteeshipClick()`，最多尝试 1 次，`IsAiControl` 表示已在托管 |

- 面板显示“当前出牌模式：脚本 / 托管 / 小杀(高级) / 小杀(王者)”，`x0(officerLevel)`：官阶 ≥ 23 显示“王者”。
- `qW()` 汇总当前状态：`standby`（目标待命）/ `off` / `trustee` / `local` / `ai`。

### 3.2 执行方式（全部为模拟操作）

- 手牌：`CardUI_Click`、`getCardUiBy(cardId)`；座位：`seatClickHandler`；按钮：`btnOK`、`btnList` + `btnClick`、`onClick`。
- 读取：`selectCardContext`、`SelectCountMin/Max`、`seatIdsRequireSelection`、`activatedCardtems`、`optionIndex`、`buttonName`。
- 离线恢复：`seat.OnlineState >= 3` 且未托管时调用 `stageMoveHandler()`。
- 技能：`seat.on('SKILL_CHANGE')` 刷新技能；国战自动亮将（`canHalfShow`）。

**迁移缺口**：新工程还没有“当前轮到我做什么”的语义模型（对应 `L4` / `actionable` / 选择上下文），这是挂机迁移的第一块基础设施。

## 4. 房间流程

### 4.1 `autoR`：进房或建房

- 单骑无双场景（`RogueLike1v1Scene`）：点 `zgs_robot_tex`（人机对战），等待 `btnListGo` 后 `onTouch(1)`；找不到按钮时提示反馈并退回普通模式。
- 模式 28 / 22（国战老友类）：`roomListView.onShowOfWindow()` → 等 `CreatOFRoomWindow` → `sureCreate()`，标记 `autoBotManagedRoom`。
- 模式 74 / 84（身份演武等）：点 `createRoomSBtn` → `CreateTableWindow`，`showMoreHandler()`；74 选“自选身份”，其余选最后一个模式；`timeBox.selectedIndex = 1`；密码 `439`；`sureBtn` 后等待 `TableScene`，选空座 `showBtns` + `sitHandler`。
- 其他模式：大厅房间列表下提示“自动挂机已待命”。

### 4.2 `autoS`：开局

1. 等 `SceneManager.IsTableScene`。
2. 按模式名识别国战老友（28）或八人身份老友（29）。
3. 百胜战功：`i3()` 准备，失败则 `baiShengNextGame` 延时重试。
4. 非房主：未准备则点 `readyBtn`。
5. 房主：托管房先 `qK()`；非托管房且非速刷时只提示“已接管出牌，不会自动补人机或代替房主开局”。
6. 模式 74：对 4 号位以前的空座逐个 `addAiHandler(1, seat)`。
7. 点 `addAiBtn`，确认弹窗选择 AI 等级（74 按官阶选“小杀(高级/王者)”，否则“小杀(普通)”）。
8. 循环点 `startUI.startBtn`，等待进入牌局或服务端 `GsCStartGameRep`（`autoBotStartAttempt` 记录请求与结果），失败则间隔重试。

### 4.3 `autoH` / `auto`：进入牌局后

- 根据 `autoBotSwitch` 选择局内循环（见 §2.1），`this.flag` 记录当前模式；无 `SelfSeatUi` 时清空。
- 国战中若有真人：发送 `mainSeatID:...:Country:...` 的 INFO 聊天（与联机辅助相关）。

### 4.4 结算与下一局（协议处理）

- 自己阵亡且其余座位全是 AI：5 秒后点 `topMenu.backBtn` 并确认“退出游戏”。
- `MsgGameOver`：重置决策状态，刷新酒馆目标进度（`xp(..., {request: true, delayMs: 1200})`）。
  - 盖主速刷：1.2 秒后 `autoS()` 补机器人并开局。
  - 百胜战功：记录结果 `vd()`，1.2 秒后 `autoS()`。
- `ClientLeavetableRep` 且原因码 `Why == xh`（房主长时间未开局被请出）：关闭盖主速刷并提示。

### 4.5 窗口处理（`ShowWindow` 之后）

- `ZZ(name)` 为真且挂机开启（或盖主速刷下的 `SelectGeneralWindow`）：自动选将 `kJ.call(win)`。
- 挂机时顺带关闭 MVP / 结算、开包、选皮肤窗口（与屏蔽设置共用同一套窗口分支）。
- `JinLan2025Window`：`ZO` + `Zg`；`SelectCountryWarGeneralWindow`：国战选将；单骑无双：`SayRogueLike1V1Window` 发言、`RogueLike1v1GameShopWindow` 商店；`RogueLike1v1ZhanJiWindow` 关闭。
- `WuGuFengDengWindow`、`SelectCardWindow`：局内 `flag > 0` 时自动处理五谷丰登、选牌。

**迁移注意**：屏蔽设置已包装 `ShowWindow`（`block-effects-controller.ts`）。挂机不能再包一层，应把窗口显示事件抽成共享服务，两边订阅。

## 5. 挂机目标（酒馆任务）

- 目标选项：无目标 / 每日胜利时间 30 分钟 / 每日游戏时间 30 分钟 / 每周胜利时间 90 分钟（依赖服务器酒馆任务进度，`TaskManager.reqTaskProgressByIds`）。
- `xL()` 刷新进度；显示“进度：x / 等待酒馆任务数据 / 未设置”。
- 已完成：
  - 挂机运行中 → `xk()` 停止挂机，提示“已完成，自动挂机已停止”。
  - 尚未启动 → `xe()` 进入待命 `autoBotTavernTargetStandby`，提示“不会启动，切换为无目标或未完成任务后将继续”。
- `xP()`：待命状态下目标变为未完成或切到无目标时，自动重新触发开关启动。

## 6. 盖主速刷（`autoBotSwitch = 9`）

- 用途：刷武将百胜战功和官阶任务。小号创建自选身份密码房当主公，大号加入并开启挂机 + 百胜战功，小号点将黄盖苦肉自杀，循环重开。
- 开启时暂存禁将方案（提示文案 `DN` / `DU`），关闭时恢复。
- 结算后自动补机器人重开；被房主请出（`Why == xh`）时自动关闭。

## 7. 自动任务（`autoTaskSwitch`）

### 7.1 触发

- 通过游戏事件 `AUTO_TASK` 触发（`Za.on('AUTO_TASK', Za, Za.task)`，约 13512 行）；登录或相关协议到达后派发，运行中再次触发时排队（`autoTaskPendingPayload`）。
- 运行锁：`autoTaskRunning` + `autoTaskRunningUntil`，守护超时约 40 秒（重试间隔 `[1s, 5s, 20s]`）。

### 7.2 流程（`task`，约 20007 行起）

依赖游戏管理器：`TaskManager`、`ActivityManager`、`NewFuLiManager`，缺一则不运行。

1. 每日武将包：`autoTaskSkipDailyWuJiangSwitch` 未开启时执行 `BZ()`（按免费倒计时 `GeneralOpenWindow.newView.freeTimeTxt` 等待，然后 `onNewOpenBag(8100101, 3)`，并用 `Wo()` 每日只领一次）。
2. 任务列表：`getTaskListFromServer()`；酒馆进度同步 `reqTaskProgressByIds`（`autoTaskTavernSwitch` 控制）。
3. 逐项处理 `gX(TaskManager)` 中未完成的可领取任务：
   - 跳过抵价券（`autoTaskSkipDiJiaQuanSwitch` + `O6`）、欢乐豆（`autoTaskSkipHuanLeDouSwitch` + `O7`）。
   - `O0()` 判断先接取还是直接领取；`O9(key)` 去重/节流；`O3()` 执行领取，成功后间隔 600 ms。
4. 公会三敲 `Bb()`（`GuildDrumWindow`，按剩余时间循环点击）、其他福利 `BW()`。
5. 另有签到、邮件（`autoTaskSkipMailSwitch`）、体验卡（`autoSignSkipSwitch`）、活动、福利树等子项分布在 `BW` 与周边函数中，迁移时逐个对照。

### 7.3 通用保护

- `Wo(key, fn)` / `Wu` / `Wj`：按账号 + 日期记录“今日已领取”，避免重复请求。
- 失败只记录警告，不中断其他子项。

## 8. 迁移计划

1. **自动任务**：独立、风险低，先做。
2. **共享设施**：
   - 窗口显示事件服务（替代各功能各自包装 `ShowWindow`）。
   - 循环与延时调度器（对应 `iE.loop` / `delay` / `clear`，按任务名去重、可整体清理）。
   - 运行 ID 取消机制。
   - “当前操作请求”模型（对应 `L4` / `actionable` / 选择上下文与按钮）。
3. **挂机最小闭环**：普通模式；自动选将、结算后继续；出牌先只用托管兜底。
4. **出牌质量**：接入小杀 AI 推荐与本地规则、超时降级。
5. **其他模式与目标**：盖主速刷、单骑无双、国战托管房、八人身份老友；酒馆目标；状态持久化与断线恢复。

## 9. 风险与验证

- 大部分逻辑只能实机长时间验证，需要为每个阶段准备实机检查清单（进房、开局、出牌、结算、下一局、断线、关闭开关后是否完全停手）。
- 自动化操作存在被游戏检测的风险，开关提示中应注明“自动化操作存在账号风险，请自行斟酌”。
