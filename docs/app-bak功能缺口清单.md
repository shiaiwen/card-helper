## 8. 建议实施顺序

| 阶段 | 建议内容 | 原因 |
|---|---|---|
| 第一阶段 | 手牌整理、明牌持久化、来源标签、断线恢复 | 直接影响局内核心使用体验 |
| 第二阶段 | 选牌全选/反选、技能连按、无密码房过滤 | 实现范围相对独立，收益明显 |
| 第三阶段 | 排位评分、推荐前三、队友候选评分 | 使用频率高，但依赖评分数据 |
| 第四阶段 | 禁将方案、百胜统计及联动 | 功能关联较强，适合一起实现 |
| 第五阶段 | 山河图奇遇影响、流派、结局记录 | 当前已有地图基础，可继续扩展 |
| 第六阶段 | 战绩、出框率、录像保存 | 需要较完整的数据模型和界面 |
| 第七阶段 | 卡背、猫猫卡牌、收集统计 | 偏个性化与统计功能 |
| 第八阶段 | 物品流水、购买统计、云同步 | 数据量大且依赖持久化服务 |
| 第九阶段 | VIP、共享授权、公告服务 | 强依赖服务端，不宜只复制前端代码 |

## 9. 实现边界

| 类型 | 是否可以仅在当前项目实现 | 说明 |
|---|---|---|
| 手牌整理、技能连按、选牌增强 | 可以 | 直接操作游戏运行时和 Vue 界面 |
| 禁将方案本地管理 | 可以 | 可使用本地配置存储 |
| 山河图影响、流派、结局记录 | 可以 | 依赖游戏配置和协议数据 |
| 卡背、猫猫卡牌 | 可以 | 依赖游戏纹理和资源刷新 |
| 排位评分 | 部分可以 | 界面可以本地实现，评分数据需要来源 |
| 战绩统计 | 部分可以 | 本地统计可实现，历史数据需要接口 |
| 云同步、VIP、共享会员 | 不可以 | 必须提供相应服务端接口和账号体系 |
| 远程公告、高阶胜率 | 不可以 | 必须有稳定的数据接口 |
