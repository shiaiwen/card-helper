# 检查更新

有两条独立的路，用同一份线上清单。面板上的按钮只打开下载页。微端启动后的自动更新会自己下载并替换安装目录。

清单地址是 `https://xc.95chong.cn/downloads/manifest.json`。下载页是 `https://xc.95chong.cn/downloads`。自动更新用的安装包是 `https://xc.95chong.cn/downloads/app.zip`。

## 清单从哪来

`npm run pack` 用工程根目录 `package.json` 的 `version` 写 `release/xiaochao-manifest.json`，并算出 `release/app.zip` 的 sha256。`app.zip` 解压后顶层是 `app/`，里面有 `package.json`。`npm run copy:portal` 把下面三个文件拷到 portal 的 `public/downloads`：

| 本地 | 网站 |
| --- | --- |
| `release/wd-xc.zip` | `/downloads/wd-xc.zip` |
| `release/app.zip` | `/downloads/app.zip` |
| `release/xiaochao-manifest.json` | `/downloads/manifest.json` |

再到 portal 目录执行 `npm run deploy`，文件才会出现在线上。清单还没发布时，这个地址是 404。

清单字段：

| 字段 | 含义 |
| --- | --- |
| `version` | 本次小抄版本，来自工程 `package.json` |
| `notes` | 说明，当前打包写空字符串 |
| `pageUrl` | 面板「有更新」打开的页面，固定为下载页 |
| `appUrl` | 必须是 `https://xc.95chong.cn/downloads/app.zip` |
| `appSha256` | `app.zip` 的 sha256，64 位小写十六进制 |

版本按点分成整数逐段比较，缺的段当 `0`。远程更大才算有更新。

游戏页在别的域名上用 `fetch` 读这份 JSON。服务器上 `xc.95chong.cn` 的 Nginx 对 `/downloads/manifest.json` 加了 `Access-Control-Allow-Origin: *`。`portal/deploy/xc.nginx.conf` 里有同样的片段，`npm run deploy` 不会改服务器上的 Nginx。

## 面板上的「检查更新」

逻辑在 `src/features/update-notice/`，按钮在工具页的版本行。

本机版本是构建时写入的 `__XIAOCHAO_VERSION__`，读不到就当 `0.0.0`。启动时不请求清单。用户点「检查更新」才去拉。

| 结果 | 按钮 |
| --- | --- |
| 远程版本更高 | 变成「有更新」。再点一次用浏览器打开 `pageUrl` |
| 远程版本不更高 | 旁边显示「已是最新」 |
| 没拿到版本号 | 旁边显示「检查失败」 |

「检查失败」包括：请求失败、超时（8 秒）、返回不是 200、清单里没有版本号。本地 `npm run dev` 也会显示这句，因为开发构建带了 `skipRemoteCheck`，点击后不发请求，版本号一直是空的。

这条路不下载 `app.zip`，不弹 UAC，不改安装目录。

## 微端启动后的自动更新

逻辑在 `tools/release-app-shell/micro-client-update.js`，窗口创建后约 0.5 秒执行。只在打包后的 Windows 微端里跑。`npm run dev` 和 macOS 直接返回。

比较的是用户数据目录里 `xiaochao.js` 头部的 `@version`，和清单里的 `version`。脚本不存在或读失败时当 `0.0.0`。

清单必须同时满足：`version` 是三段数字、`appUrl` 去掉查询参数后正好是上面的 `app.zip` 地址、`appSha256` 是 64 位小写十六进制。少任何一项就当作没有更新。网络失败同样跳过，不挡启动。

版本更高时弹出「立即更新 / 暂不更新」。选立即更新后：

1. 把 `app.zip` 下到用户数据目录 `xiaochao-update/app-<版本>.zip`。
2. 核对 sha256。不一致就删掉包并提示失败。
3. 弹出说明，接着弹出 Windows UAC。点「是」后微端退出。
4. 提权后的脚本等进程结束，把 `resources/app` 改名为 `app.xiaochao-backup`，再把压缩包里的 `app` 移进去，然后重新打开微端。替换失败会把备份移回去再启动。

点「否」或 UAC 被取消时，继续用当前版本。

已经装在电脑里的旧微端没有这段代码。要先用 `wd-xc.zip` 手动安装一次带自动更新的壳，之后发新版本才会自己弹。新版本的 `package.json` `version` 必须比用户正在用的脚本 `@version` 更高，否则两边都认为已是最新。
